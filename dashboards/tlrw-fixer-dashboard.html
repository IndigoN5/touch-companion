TLRW Code Fixer — User Manual

Version 2.0 • NUVABASE Professional Consulting

What This Tool Does

The TLRW Code Fixer analyzes Python code for common bugs, style issues, and architectural problems. It uses a four-phase process (Think, Learn, Reflect, Write) with triple redundancy to find and fix issues automatically.

How to Use It

  • Step 1: Paste your Python code in the "Input Code" tab, or click "Upload .py File" to load a file from your computer.
  • Step 2: Click the green "Run TLRW Cascade" button.
  • Step 3: Watch the TLRW phases light up as the analysis runs.
  • Step 4: Review results across the tabs: Analysis Results, Issues Found, Before/After, Full Report.

Understanding the Tabs

  • Analysis Results: KPI cards showing issue count, confidence score, fix level. Bar chart of issues by category. Gauge showing overall confidence.
  • Issues Found: Every issue detected, with line number, category (surface/structural/systemic), and description.
  • Before / After: Side-by-side view of original vs. fixed code, plus a line-by-line diff showing exactly what changed.
  • Full Report: Complete text report you can copy, print, or save.

What the Fixer Detects (25+ Patterns)

  • Surface: Python 2 prints, None comparisons, boolean comparisons, trailing whitespace, f-strings without placeholders, missing docstrings.
  • Structural: Bare excepts, silent exception swallowing, wildcard imports, assert statements, return in __init__, duplicate dict keys.
  • Systemic: Mutable default arguments, excessive nesting, long functions, global usage, magic numbers, string concat in loops.

The TLRW Process

  • THINK: Atomic deconstruction — detect all issues using line-level heuristics and AST analysis.
  • LEARN: Extract coding conventions (indentation, quote style, naming patterns, imports).
  • REFLECT: Generate three independent fix layers (surface, structural, systemic) and calculate divergence.
  • WRITE: Select the "golden fix" through agent discovery and cross-validation.
Tip: Click "Load Sample Code" to see a demo with intentionally buggy code.

Privacy

All analysis runs entirely in your browser. No code is sent to any server. 100% private.

Glossary of Terms

TLRW Methodology
TLRW
Think, Learn, Reflect, Write — four-phase analysis methodology with 12 quality gates.
Cascade
The full TLRW pipeline: Think → Learn → Reflect → Agent Discovery → Write.
Triple Redundancy
Three independent fix layers (surface, structural, systemic) that cross-validate each other.
Golden Fix
The best fix selected after comparing all three redundancy layers.
Divergence Score
Measures how different the three fix layers are. Low divergence = high confidence.
Agent Discovery
Cross-validation phase that checks fixes for correctness before selecting the golden fix.
Issue Categories
Surface Issue
Style and formatting problems (trailing whitespace, print statements, None comparisons).
Structural Issue
Pattern and relationship problems (bare excepts, silent errors, missing error handling).
Systemic Issue
Architectural and logic problems (mutable defaults, excessive nesting, global state).
Syntax Issue
Code that won't parse at all (invalid Python syntax).
Python Terms
AST
Abstract Syntax Tree — Python's internal code structure used for deep analysis.
Mutable Default
Using [] or {} as a function default argument. Dangerous because it's shared between calls.
Bare Except
"except:" without specifying an exception type. Catches everything including system exits.
Docstring
A documentation string at the start of a function/class explaining what it does.
PEP 8
Python's official style guide. Many fixer rules enforce PEP 8 conventions.
Dashboard Terms
KPI
Key Performance Indicator — summary numbers at the top of the results page.
Diff
A comparison showing exactly what lines changed between original and fixed code.
Confidence
How sure the fixer is that its fix is correct (based on how many layers passed validation).
Primer ID
A unique fingerprint (hash) of the original code being analyzed.
